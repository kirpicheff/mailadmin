# План реализации глобальных рассылок (на все домены) без хардкода

Этот документ описывает пошаговый план внедрения функции «Рассылка на весь сервер» в панель администрирования MailAdmin и необходимые настройки на почтовом сервере (Postfix).

---

## 1. Изменения на почтовом сервере (Postfix)

Чтобы Postfix динамически собирал список получателей для глобального алиаса без хардкода конкретных адресов в конфигурационных файлах, используется специальный SQL-запрос.

### А. Изменение SQL-запроса в `mysql_virtual_alias_maps.cf`
В файле `/etc/postfix/mysql_virtual_alias_maps.cf` необходимо обновить секцию `query` для возврата списка строк вместо GROUP_CONCAT:

```ini
query = SELECT goto FROM alias WHERE address='%s' AND active = '1' AND goto != '[ALL_MAILBOXES]'
        UNION 
        SELECT username FROM mailbox WHERE domain='%d' AND '%s'='all@%d' AND active='1'
        UNION
        SELECT username FROM mailbox WHERE active='1' AND EXISTS (
            SELECT 1 FROM alias WHERE address='%s' AND goto='[ALL_MAILBOXES]' AND active='1'
        )
```

**Как это работает:**
1. Первая часть `SELECT` находит обычные алиасы (исключая маркеры `[ALL_MAILBOXES]`).
2. Вторая часть `SELECT` возвращает список адресов (по одной строке на ящик) для конкретного домена, если получатель равен `all@domain.com` (динамическая рассылка на уровне домена).
3. Третья часть `SELECT` срабатывает только в том случае, если в таблице `alias` существует активная запись для запрашиваемого адреса `%s` с получателем `[ALL_MAILBOXES]`. В этом случае она выбирает адреса всех активных ящиков со всего сервера по одной строке на ящик.
Этот подход полностью решает проблему с ограничением длины `GROUP_CONCAT` (`group_concat_max_len`), так как адреса возвращаются отдельными записями, которые Postfix прекрасно обрабатывает.

## 2. Безопасность и защита от внешнего спама (без хардкода)

Поскольку рассылка отправляет письма абсолютно всем пользователям сервера, её необходимо защитить от писем из внешней сети. Для этого мы заставим Postfix проверять статус адреса получателя прямо в базе данных.

### А. Создание MySQL-карты для блокировки
Создается новый файл конфигурации для Postfix, например `/etc/postfix/mysql_restrict_global_aliases.cf`:

```ini
user = mailadmin
password = password_from_config
hosts = 127.0.0.1
dbname = postfix
query = SELECT 'REJECT access denied' FROM alias WHERE address='%s' AND goto='[ALL_MAILBOXES]' AND active='1'
```

### Б. Подключение проверки в `main.cf`
В файле `/etc/postfix/main.cf` в секции `smtpd_recipient_restrictions` подключается созданная MySQL-карта после разрешающих правил авторизации:

```postfix
smtpd_recipient_restrictions =
    ...
    permit_sasl_authenticated,
    permit_mynetworks,
    # Динамическая блокировка внешних писем на любые глобальные рассылки
    check_recipient_access mysql:/etc/postfix/mysql_restrict_global_aliases.cf,
    reject_unauth_destination,
    ...
```

Таким образом, любой созданный в панели глобальный алиас автоматически и мгновенно защищается от спама без необходимости редактирования каких-либо файлов на сервере.

## 3. Изменения в Панели Администрирования (MailAdmin)

### А. Локализация (Frontend)
В файлы локализации (`frontend/src/i18n/locales/ru.json` и `en.json`) необходимо добавить строки для нового чекбокса и отображения статуса:
* `alias_form.all_mailboxes_label` — «Рассылка на весь сервер (все домены)»
* `alias_form.all_mailboxes_hint` — «Письмо будет доставлено всем активным пользователям на сервере»
* `alias.all_mailboxes_display` — «[Все пользователи сервера]»

### Б. Компонент формы алиаса (`AliasForm.vue`)
1. **Чекбокс в интерфейсе:** Добавить чекбокс «Рассылка на весь сервер» (показывать только если текущий пользователь — SuperAdmin).
2. **Логика формы:**
   * При включении чекбокса текстовое поле `Goto` блокируется (`disabled`) и заполняется значением `[ALL_MAILBOXES]`.
   * При отправке формы на бэкенд передается `goto: "[ALL_MAILBOXES]"`.
3. **Выбор домена:**
   * Глобальный алиас привязан к конкретному домену в таблице `alias`. SuperAdmin должен иметь возможность выбрать любой существующий домен из доступных в выпадающем списке при создании рассылки.

### В. Компонент списка алиасов (`Aliases.vue` / `Mailboxes.vue`)
В таблице списка алиасов в колонке «Получатели» (`Goto`):
* Добавить проверку: если значение равно `[ALL_MAILBOXES]`, выводить красивый бейдж «Все пользователи сервера» вместо сырого текста.

## 4. Проверка и валидация на Backend (Go)
1. **Создание и обновление алиасов:**
   * Бэкенд на базе Go по умолчанию проверяет только наличие поля `goto` (правило `required`). Никаких дополнительных правок в валидатор не требуется, так как строка `[ALL_MAILBOXES]` успешно пройдет проверку.
2. **Права доступа:**
   * Бэкенд должен жестко контролировать права доступа на основе роли пользователя:
     * Запретить создание нового алиаса с `goto = "[ALL_MAILBOXES]"`, если пользователь не является `SuperAdmin` (возвращать `403 Forbidden`).
     * Запретить изменение или удаление любого существующего алиаса с `goto = "[ALL_MAILBOXES]"` для пользователей без роли `SuperAdmin` (возвращать `403 Forbidden`).
     * Запретить изменение получателя (`goto`) существующего обычного алиаса на `[ALL_MAILBOXES]` для пользователей без роли `SuperAdmin` (возвращать `403 Forbidden`).
